# PolicyRAG 第一版产品定义

## 1. 产品问题

企业内部制度通常分散在 PDF、Markdown 等文件中。员工直接搜索时难以判断关键词是否准确，通用聊天模型又可能脱离原文回答。系统需要同时解决证据检索、来源定位和访问权限三个问题。

## 2. 用户角色

| 角色 | 主要能力 |
| --- | --- |
| 管理员 | 创建知识库、上传文档、查看处理状态、配置知识库权限 |
| 普通员工 | 查看授权知识库、提出制度问题、打开答案引用 |
| 未授权用户 | 不应看到受限知识库、文档、分块或引用内容 |

## 3. 用户故事与验收条件

### 3.1 管理员上传制度文档

**Given** 管理员已登录并拥有一个知识库的管理权限  
**When** 管理员上传合法的 PDF 或 Markdown 文件  
**Then** 系统保存文档，解析正文和引用位置，并把状态从 `uploaded` 经 `processing` 更新为 `ready`

**And** 每个分块必须保留 `document_id`、`chunk_index` 和页码或章节路径

**异常条件**

- 空文件、损坏文件和不支持格式不应进入 `ready`
- 处理失败时显示可理解的错误，并保存 `failed` 状态
- 同名文件不能覆盖其他文档；重复文件不能生成重复有效分块

### 3.2 员工获得带真实引用的答案

**Given** 员工有权访问指定知识库，且知识库中存在相关制度  
**When** 员工提出一个资料中可以回答的问题  
**Then** 系统返回答案、至少一个真实引用和原文定位

**And** 引用编号必须对应本次检索返回的授权分块

**And** 点击引用可以查看文档名称、页码或章节以及原文片段

**异常条件**

- 模型输出不存在的来源编号时必须删除
- 没有有效引用时不得保存为成功答案
- 检索失败和模型失败必须显示明确状态

### 3.3 员工访问未授权知识库

**Given** 普通员工未获得 Finance 知识库的访问权限  
**When** 员工在列表中查找 Finance，或直接请求 Finance 的文档、分块和引用  
**Then** 系统不得返回 Finance 的任何业务内容

**And** 文档详情、搜索和引用查看接口都执行相同的服务端权限检查

**异常条件**

- 手工修改请求中的 `kb_id` 不能扩大权限
- 删除授权后，历史引用中的原文不能被继续读取
- 前端隐藏页面不能替代后端鉴权

### 3.4 系统在证据不足时拒答

**Given** 授权知识库中不存在回答问题所需的证据  
**When** 员工提出问题时  
**Then** 严格模式下系统明确说明无法从现有资料回答

**And** 系统不应让模型使用资料外知识补全答案

## 4. P0 范围

- 邮箱密码登录和基础身份
- 管理员、普通员工和知识库授权
- PDF、Markdown 上传
- 正文解析和可定位分块
- 一个中文 Embedding 模型
- pgvector 向量检索
- BM25 或 PostgreSQL 全文检索
- RRF 混合排序
- 权限过滤
- 单模型回答和提取式降级
- 引用保存与校验
- 证据不足拒答
- 40 题评测集
- Docker Compose 启动

## 5. P1 范围

- 流式回答
- 文档重新上传和增量更新
- 检索重排序
- 多轮问题改写
- 两个组织之间的数据隔离验证
- 更完整的文件和异常处理

## 6. 非目标

- Agent 工具调用
- Text-to-SQL
- 数据库、Web 和 SaaS 连接器
- 多种模型供应商适配
- 复杂团队角色继承
- 计费、Webhook 和审计导出
- 大规模并发和分布式向量数据库

## 7. 阶段 0 完成判定

- 三个核心用户故事均有 Given-When-Then 验收条件
- P0、P1 和非目标已经冻结
- 每个 P0 能力都能对应一个可运行或可测试的结果
- 不把 CSV-AI v3 现有功能算作本仓库个人成果
- 后续阶段有明确顺序和停止条件
